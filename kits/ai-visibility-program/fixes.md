# Fixes

Find the code the [check-up](glossary.md#support-code) printed, or the one a step pointed to, read the row and try the fix. Codes E40 to E52 cover failures a team meets at scale. Codes E90 to E95 come from the check-up command. Many setup and run problems are the same as in the single-site kit, so the [single-site fixes](../ai-visibility/fixes.md) (E30 to E39 for the full version) apply here too.

If a fix does not work, send the [step ID](glossary.md#step-id) and the [support code](glossary.md#support-code) to Pigasus Group at https://pigasus.group/contact. Setup questions are free.

| Code | What you see | Why | The fix | Step |
|---|---|---|---|---|
| E40 | The month passed and the [ledger](glossary.md#ledger) has no row for it, or the daily check says MISSED | The scheduled job never started: the machine was off or asleep, [cron](glossary.md#cron) could not find `python3`, or it lacked permission to read the folder | Run `python3 run_program.py run` by hand now, then fix the cause. Use full paths in the cron line, give cron permission to the folder, and keep the daily check on a second machine. Add a row to the incident log | AP-FU-03-5 |
| E41 | `run_program.py` says it cannot read `config.json`, or the check-up says the config is invalid | A missing quotation mark or comma, an empty `sites` list, or a `program` block that was deleted | Compare your file with `config.example.json` line by line. Fix the line the message names | AP-FU-01-4 |
| E42 | A site is marked FAILED after its retries | The key, model name or limit is wrong for that site, or an AI company had an outage | Read `logs/<month>-<site>-attempt2.log`. A 401 or 403 means the key, a 429 means a limit or no credit, and "model not found" means the model name. Fix it, then run `python3 run_program.py run --site <id> --force`. The failed attempts stay in folders ending `.failed-1` | AP-FU-03-2 |
| E43 | A run covers only some of the companies, and one company's answers are empty | One provider's key was missing or its request failed while the others worked | Find the empty company in the log, fix its key, and rerun that site with `--force`. Never report the partial run as a full one. Mark the missing company "not run" in the report | AP-FU-03-2 |
| E44 | The question battery says visibility is up and a platform or [Search Console](glossary.md#search-console) says it is down, or the reverse | The sources measure different things: different question sets, competitors, AI products or model versions, collection methods, dates or locations | Run `unified-visibility`, work through the reasons, and record the one that applies in `reports/disagreements.md`. If none applies, treat the change as a lead, not a finding. Do not average the sources or pick the friendlier one | AP-FU-04-4 |
| E45 | The same question gives different answers each run, and a "named" flips back and forth | AI answers vary from one ask to the next, and models change quietly | Do the repeat test in the [noise audit](glossary.md#noise-audit) and write down the noise level. Report changes of a cell or two as within normal variation. Record the model name every run so a model swap is visible | AP-FU-04-1 |
| E46 | Runs stop with 429 or "quota" errors, or the bill is far above plan | The monthly cap is too low, several sites share one key, or retries re-asked every question | Raise the cap deliberately, or run fewer companies. Multiply sites by questions by companies before scheduling. Lower `max_attempts` to 1 if cost is the problem | AP-FU-03-1 |
| E47 | A fix from the handoff is on the ticket as done, but the page or `robots.txt` has not changed | The [CMS](glossary.md#cms) publish failed, a deploy did not go out, or a cache still serves the old page | Fetch the page yourself and write what you see in `reports/fixes-log.md`. Ask the web team to republish. Do not count the fix in the trend until it is verified live | AP-FU-04-6 |
| E48 | The alert never reached the channel, or the program prints "No alert sent" | The [webhook](glossary.md#webhook) variable is not set in the scheduled job, the address changed, or the channel was archived | Put the variable in `.env`, run `python3 run_program.py check --test-alert`, and create a new webhook if the address is dead. Until it works, read the ledger every morning | AP-FU-03-6 |
| E49 | The program skips a site and says the [slot](glossary.md#slot) already has a good run, but the run looks wrong | A good row is already in the ledger, so the site is not run again | Rerun on purpose with `--force`. The old run folder is replaced, so move it aside first if you want to keep it | AP-FU-03-8 |
| E50 | Someone in the review asks whether a change is real and the report has no answer | The report gave a number without its noise level or sources | Add the repeat-test result and the file behind the number. If neither exists, say "not verified" and run the check before the next review | AP-FU-04-5 |
| E51 | Two sites' numbers do not match when someone adds them up | The sites use different question sets, markets or versions, so they are different instruments | Report them in separate rows and never total them. If leaders need one figure, say that none is honest and show the rows | AP-FU-04-5 |
| E52 | The daily check says NEEDS REVIEW for a site | `scored.csv` is missing because nobody has corrected the draft | The reviewer reads each answer, fixes the draft rows, and saves `scored.csv` in the run folder. Until then, the numbers are unverified and stay out of the report | AP-FU-03-3 |
| E90 | The check-up says your [Python](https://www.python.org/downloads/) is too old | The program that runs the scripts is out of date | Install a current Python 3 from python.org, open a new [terminal](glossary.md#terminal) and run the check-up again | AP-FU-01-1 |
| E91 | The check-up says the kit folder is not present | It was run from the wrong folder, or the kit was not downloaded | Follow [Get the kit files](../../guides/get-the-files.md), then run the check-up from the unpacked folder | AP-FU-01-2 |
| E92 | The check-up says `config.json` is not present | The file was not copied from `config.example.json`, or it is in another folder | Copy it into your program folder and pass the path with `--config` | AP-FU-01-4 |
| E93 | The check-up says `config.json` is not valid or a key is empty | A comma or quotation mark is missing, or a required block is empty | Fix the line it names and fill the `program` and `sites` blocks | AP-FU-01-4 |
| E94 | The check-up says an [environment variable](glossary.md#environment-variable) name is not set | A key was typed in a terminal that has since closed, or it is not in `.env` | Add the name to `.env` (names only are checked, never values) | AP-FU-01-5 |
| E95 | The check-up skips `claude` or `python3` | The optional command is not on your path | Install it or open a new terminal. The program still runs without `claude` if you paste files into another tool | AP-FU-01-1 |

## When the fix is not in this table

Write down the step ID, the support code and the last few lines of the relevant file in `logs/`. A person can usually read those and tell you where you are stuck. Send them to Pigasus Group at https://pigasus.group/contact. Setup questions are free.
