# IP-FR-03: Research and Brief

You will gather the facts for one post and write a brief (a one- or two-page plan for that single post). Allow about an hour per post. Never skip the step that has you open every source.

1. **IP-FR-03-1.** Add your site to Search Console (Google's free tool that shows which searches reach your site). Go to search.google.com/search-console and choose Add property. Choosing the domain option is best; it asks you to add a small record at your domain's DNS settings (the settings where your web address is managed), which your website host or domain provider can help with. See the [keys and accounts guide](../../../guides/keys-and-accounts.md) for each account.
   You'll know it worked when Search Console says the property is verified. If it will not verify, or shows no data, it's E10. Data only appears from the day you verify, so do this first even if you wait to use it.

2. **IP-FR-03-2.** Copy the verified property name (it looks like sc-domain:example.org) into the search_console_property row of your Setup tab.
   You'll know it worked when that Setup row is filled. This row is optional for the [check-up](../glossary.md#check-up).

3. **IP-FR-03-3.** In your browser, search the main phrase for your post and read the first page of results. Copy the top ten titles and web addresses, and any "People also ask" questions, into a Doc named for the post.
   You'll know it worked when you have ten titles and at least a few questions written down.

4. **IP-FR-03-4.** If you have Search Console data, open Performance, filter to queries containing your phrase, and copy the rows. These show what real readers already type.
   You'll know it worked when you have a short list of real searches or a note that there is no data yet.

5. **IP-FR-03-5.** Run [prompt](../glossary.md#prompt) 4 with what you gathered. Read its answer about what searchers want and what the top results leave out.
   You'll know it worked when you have a one-sentence description of the searcher's goal and a list of gaps.

6. **IP-FR-03-6.** (Optional.) Run prompt 5 to hear from five pretend readers. Treat the answer as brainstorming only. Then ask five real people the same question in person or by message if the post matters.
   You'll know it worked when you have a short list of repeated objections.

7. **IP-FR-03-7.** Find the facts yourself. Search for statistics from named sources such as government agencies, universities, and recognized nonprofits. Open each source and copy the exact number, organization, year, and report title into your Doc. Do not accept a number just because the [AI model](../glossary.md#ai-model) produced it.
   You'll know it worked when each statistic has a source you opened. If a number cannot be found at its source, throw it out; this is the most common problem, E08.

8. **IP-FR-03-8.** List up to eight pages on your own site the post could link to.
   You'll know it worked when each has a web address and a phrase to use as the link.

9. **IP-FR-03-9.** Run prompt 6 to write the brief, then prompt 7 to check its structure. Fix every "no" answer.
   You'll know it worked when the brief has all ten headings and a verdict (new post, [refresh](../glossary.md#refresh), hold, or skip). If the verdict is not "new post", stop and resolve it.

10. **IP-FR-03-10.** Save the brief as a Google Doc in your briefs folder, paste its link into the brief_link cell of the post's [Queue](../glossary.md#queue) row, and set the stage to Planned.
    You'll know it worked when the Queue row shows the link and stage Planned.

Next, [IP-FR-04, draft and check](IP-FR-04-draft-and-check.md).

> **How to get help.** Write down the [step ID](../glossary.md#step-id) where you got stuck (it looks like IP-FR-01-3). If your kit has a check-up button or command, run it and copy the [support code](../glossary.md#support-code) it prints. Then send both to Pigasus Group at https://pigasus.group/contact. Setup questions are free.
