# Fixes

Find your code in the first column. Each guide names the code when a step goes wrong. The first six rows are setup problems. The rest are the failures a team meets once the kit is running. A [slot](glossary.md#slot) is one scheduled run time of a [scheduled job](glossary.md#scheduled-job), a [retry](glossary.md#retry) runs it again, and an [outcome row](glossary.md#outcome-row) is the log line that says how it ended. If your problem is not here, write to Pigasus Group at https://pigasus.group/contact with the [step ID](glossary.md#step-id) and your [support code](glossary.md#support-code). Setup questions are free.

Codes from E90 to E95 come from the command-line [check-up](glossary.md#check-up) that every kit shares. They're explained in [getting help](../../guides/getting-help.md).

| Code | What you see | Why | The fix | Step |
|---|---|---|---|---|
| E01 | "claude: command not found" | [Claude Code](glossary.md#claude-code) is not installed, or the [terminal](glossary.md#terminal) was open before it was | Follow the shared install guide again, close the terminal, open a new one and type `claude --version` | TO-FU-01-1 |
| E02 | "python3: command not found", or a version below 3.9 | [Python](glossary.md#python) is missing or old | Install a current Python 3 from python.org, open a new terminal and retry | TO-FU-01-2 |
| E03 | The [plugin](glossary.md#plugin) or [marketplace](glossary.md#marketplace) is not found, or a [skill](glossary.md#skill) is missing or ignored | The [repository](glossary.md#repository) address was copied incompletely, or Claude Code needs a restart, or the request did not name the skill | Copy the address again from the repository's front page. Type `/exit`, start `claude` again, and name the skill ("use the capability-ledger skill") | TO-FU-01-3, TO-FU-01-7 |
| E04 | `config.json` is missing, or the [check-up](glossary.md#check-up) says it is not valid | The file was not copied from `config.example.json`, or a quote or comma is wrong in the [JSON](glossary.md#json) | Copy the example again and edit one line at a time, checking with the one-line test in TO-FU-01-4 | TO-FU-01-4, TO-FU-01-5 |
| E05 | The ledger checker says "missing header line" or "proof path not found" | The header has no real date, or a Proof entry names a file the checker cannot see | Write the header as `Last verified against repo: 2026-11-13 by your name`. Fix the file name in the Proof column, or run the checker with `--root` pointing at the right folder | TO-FU-01-8 |
| E06 | The runner says the [registry](glossary.md#registry) is not found | You ran it from a folder without `jobs.json` | Move into the folder that holds `jobs.json`, or pass `--registry /full/path/jobs.json` | TO-FU-02-4, TO-FU-02-6 |
| E07 | The watcher reports missed slots for jobs that did run, or its log never grows | The schedule in `jobs.json` does not match when the job really runs, the time zone differs, or the [scheduler](glossary.md#scheduler) line has the wrong folder | Match the registry's time and weekday to the real schedule, use full paths in the scheduler line, and confirm the machine's clock and zone | TO-FU-02-7 |
| E08 | A stuck slot is in `flags.md` but nobody was told | The alert address is not set where the scheduler runs, the chat tool rejected it, or nobody reads that channel | Set `JOB_ALERT_WEBHOOK` in the crontab itself, use the chat tool's test button, and name a person who reads the channel the same day. A flag that cannot be delivered is a failure | TO-FU-02-8 |
| E09 | A job exits cleanly but the outcome row says "output-missing", or the report reads an old file | The script finished without writing its output, or wrote it somewhere else, so a stale success is standing in for the run | Make the script write the file named as `output_file` in `jobs.json`. Check freshness of the file and not the exit code alone. Never let an older file count for a new slot | TO-FU-02-5 |
| E10 | A pull fails with a [quota](glossary.md#quota) or rate-limit message, or the platform bills for overage | Several scripts or retries are calling the same [API](glossary.md#api), or the [quota](glossary.md#quota) is smaller than the schedule needs | Pull each source from one [capture point](glossary.md#capture-point), widen the retry delays, mark the job not safe to repeat until it skips what it already has, and check the plan's limits on the vendor's page | TO-FU-02-3, TO-FU-02-4 |
| E11 | A [CMS](glossary.md#cms) publish or read fails on a schedule, or only some pages go through | An expired token, a page that changed shape, or a [quota](glossary.md#quota) on the CMS API | Read the outcome row's evidence lines, renew the token in the environment and not in a shared file, and rerun the same slot. Hold any report that reads the failed output | TO-FU-02-9 |
| E12 | Two platforms show the metric moving in opposite directions | Different dates or time zones for day boundaries, a feed that started late, address variants such as www or trailing slashes, or two measures that are not comparable | Compare the same window and the same pages, check each source's first date of history, and mark the figure "direction disputed" until the cause is found. Do not act on it | TO-FU-04-4 |
| E13 | AI-visibility figures change from run to run with no change on your side | AI answers vary between runs, models and versions, and a different question set or location changes who is named. These are common causes to check, not proof for your platform | Keep the question set fixed and written down, label the model and date on every figure, compare more than one run, and report the range. Treat a single run's move as unproven | TO-FU-04-3 |
| E14 | The brief checker reports a missing header line or section | Purpose, [Session](glossary.md#session), Compactions or the "Settled, never re-ask" heading is missing | Put the three header lines first and keep the heading text exactly as the template has it | TO-FU-03-2, TO-FU-03-4 |
| E15 | The inventory finds 0 repositories | `projects_folder` points at the wrong place, or the folders are not tracked as [repositories](glossary.md#repository) | Set `workspace.projects_folder` in `config.json` to the folder that holds your workstreams and check that each has a `.git` folder | TO-FU-03-7 |
| E16 | The [design gate](glossary.md#design-gate) exits with code 2 and prints "could not run" | Nothing was measured: no browser, an address that does not answer, a bad config, or the wrong copy of the site on that port | Read the one line it prints, start your local site, check the port, and use the gate's marker option to confirm the copy. Code 2 is never a pass | TO-FU-03-10 |
| E17 | The report checker warns about an ungraded cause, a figure with no source, or a [single-source](glossary.md#single-source) | The report states a cause without a grade, or a number without a date or platform | Add the grade (holds, weakened or refuted) and its evidence, add the source and data-through date, or label the figure single-source. If a check can be done now, do it now | TO-FU-04-5 |
