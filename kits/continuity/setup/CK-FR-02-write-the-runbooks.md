# CK-FR-02 Write the Runbooks

You will write the pages a stranger would need. Pick the two or three weakest functions first. Trying to document everything at once tends to document nothing.

1. **CK-FR-02-1.** Choose which [runbooks](../glossary.md#runbook) to write first. Look at the BusTest [tab](../glossary.md#tab). A function scoring 0 or 1 that would stop money or work within days comes first, even if you like the way it runs today. Money usually goes first.
   You'll know it worked when you have a short list of two or three names written on the Sheet's next_step column.
2. **CK-FR-02-2.** Make a Google Docs file for each runbook (Docs is Google's free word processor at docs.google.com). Open the matching template in the kit, copy all of it, paste it into the new document, and name it, for example Money Runbook. The templates are `free/runbook-money.md`, `runbook-operations.md` and `runbook-access.md`.
   You'll know it worked when each Doc shows the template headings and the blank lines "______".
3. **CK-FR-02-3.** Fill in the [money runbook](../free/runbook-money.md). Where it asks for an account, write the bank and the last four digits, never the whole number. Where it touches a login, write only that the login is in the [password manager](../glossary.md#password-manager).
   You'll know it worked when every blank is either filled or marked unknown. Mark an unknown blank with a question mark so you can find it again.
4. **CK-FR-02-4.** Fill in the [operations runbook](../free/runbook-operations.md). Write it the way you would teach a new hire on their first day. For "when something breaks," write the three things that go wrong most and what you do.
   You'll know it worked when a person who has never seen your shop could follow the opening list step by step.
5. **CK-FR-02-5.** Fill in the [access runbook](../free/runbook-access.md). Name the password manager and who can reach it in an emergency, then write the [recovery path](../glossary.md#recovery-path) for each account you could not run the business without. Do not write a password anywhere in this document. If one slips in, delete it, change the password, and see E12 in [fixes.md](../fixes.md).
   You'll know it worked when each critical account has an owner, a recovery email, a place where the backup codes are kept and the steps to get back in.
6. **CK-FR-02-6.** Share each Doc with your stand-in as view only. In Docs choose Share, type their email address, pick Viewer, and send. Also tell them in person or by phone where the documents are.
   You'll know it worked when your stand-in can open each Doc from their own account. If they see a request-access page, the Share step was missed.
7. **CK-FR-02-7.** Put the document's name beside each function in the next_step column of the BusTest tab, so the sheet and the Docs point at each other.
   You'll know it worked when each function you wrote has a Doc named in its row.

> **How to get help.** Write down the step ID where you got stuck (it looks like CK-FR-02-3). If your kit has a [check-up](../glossary.md#check-up) button or command, run it and copy the [support code](../glossary.md#support-code) it prints. Then send both to Pigasus Group at https://pigasus.group/contact. Setup questions are free.
