# Fixes

Find the code the guide or the check-up gave you. If your code is not here, send it to Pigasus Group (see the box at the end of any guide) and the fix goes in for the next team.

| Code | What you see | Why | The fix | Step |
|---|---|---|---|---|
| E16 | [Looker Studio](glossary.md#looker-studio) shows "Data set configuration error" or an empty list | The sheet moved, was renamed, lost sharing permission, or the tab is empty | Reconnect the data source under Resource, Manage added data sources, Edit. Confirm you can open the sheet yourself, and that the account behind the dashboard still has access | MR-FU-03-9 |
| E17 | Two platforms disagree about up or down, again | A feed that started late, address variants (www, trailing slash, fragments), different day boundaries or time zones, filters, or two tools that read the same upstream data and so count as one | Match the date windows exactly, compare like pages and channels, check each source's first day of history, and check the [source map](glossary.md#source-map) for tools that share a source. Until explained, write [direction disputed](glossary.md#direction-disputed) and do not act | MR-FU-03-5 |
| E19 | An error mentions 403, "permission" or "no access" on a pull | The [service account](glossary.md#service-account) is not listed on that property, or lost its access when someone changed the property | In [Search Console](glossary.md#search-console), Settings, Users and permissions, confirm the account is listed as Restricted. In [GA4](glossary.md#ga4), Admin, Property access management, confirm at least Viewer | MR-FU-02-1 |
| E22 | "command not found", or a [skill](glossary.md#skill) is missing in Claude Code | The tool was not installed, the terminal needs reopening, or the kit was not added | Close and reopen the terminal, run the version check from the shared install guide and add the kit again | MR-FU-01-1 |
| E25 | The [Clarity](glossary.md#clarity) pull says no [token](glossary.md#token) was found | The token file name does not match the project name, or the [environment variable](glossary.md#environment-variable) has a different name | Name the file `<project>.token` in `~/.config/clarity/`, or set `CLARITY_TOKEN_<PROJECT>` with letters and underscores only | MR-FU-02-3 |
| E26 | The Clarity pull says the daily limit is used | Clarity allows only a few requests per project per day, and several jobs or people share the count | Wait until tomorrow. Give each scheduled job a fixed number of calls and keep a few spare for questions | MR-FU-02-3 |
| E29 | A skill read the wrong site, or says the site is "not listed" | The settings file or the `GSC_SITES` list is for another property, or a site was copied without changing its IDs | Check `search_console_site` and `ga4_property_id` in that site's folder, and that the site is in `GSC_SITES` spelled exactly as Search Console shows it. Never mix two sites' exports in one run | MR-FU-01-3 |
| E30 | A pull or report is late and nobody knows whose job it was | The job has no named owner or backup, or the owner left | Put one name and one backup on the job in the owner table. Re-run it by hand today | MR-FU-01-4 |
| E31 | A report shows a drop or gain that lines up with a tracking or definition change | A [tag](glossary.md#tag), [event](glossary.md#event) name, form or lead definition changed inside the comparison window | Compare like with like or leave the figure out and say why. Record the change in the [change log](glossary.md#change-log). Never present a reclassification as a decline | MR-FU-01-6 |
| E32 | A scheduled pull missed its slot, or the [run log](glossary.md#run-log) has no line for it | The machine was off, the job was never scheduled, a key expired or the command failed | Run it by hand today and log the retry. Check the [scheduler](glossary.md#scheduler), then the key. Mention the gap in the report's caveats. A missed slot counts as a failure even when older data is still fresh | MR-FU-02-5 |
| E33 | The AI-visibility numbers change from run to run on the same questions | AI answers vary by nature, and platforms differ in prompts, engines, models and collection | Never read one run as a trend. Compare several runs of the same question set, name the engine and the base on every rate, and confirm direction on a second platform before acting | MR-FU-03-5 |
| E34 | A [CMS](glossary.md#cms) publish or a Tag Manager publish fails or does not appear | The account lacks publish rights, the workspace has a conflict, or the draft was not submitted | Ask the [container](glossary.md#container) or CMS owner for publish rights. For tracking, test in preview first, import with Merge and renaming conflicts, never Overwrite, and publish only after the test passes | MR-FU-03-2 |
| E35 | An [API](glossary.md#api) call stops with a quota or rate-limit message | Too many jobs share one key or project, or a pull asks for more rows than allowed | Stagger the schedule, cut the row request to what the report needs and check the vendor's current limits. Do not create extra keys to get around a limit | MR-FU-02-4 |
| E36 | `verify_capture.py` says "not adoptable" | The capture is stale, ended too close to today, or reached the row cap | Take a fresh capture, narrow the request if it hit the cap, and report from the verified one only | MR-FU-02-7 |
| E37 | Pulls started failing after a person left the team | Their token, account or sharing permission was the one the job used | Rotate the token, move the job to a team-owned account and update the owner table. Rotate secrets whenever someone with access leaves | MR-FU-02-1 |
| E38 | The dashboard and the report show different figures | The dashboard sheet was not refreshed, or the report used a different filter or date range | Rebuild the numbers table from the same sources, rerun `looker-export` and validate. Put the filter and dates beside every figure | MR-FU-03-9 |
| E39 | `evidence-review` fails the report | A cause has no grade, a number has no dated source, a borrowed statistic is a weak tier, or a hypothesis sits in the action list | Fix each blocker it names, move hypotheses to "Investigation needed" and run it again. The reviewer should not be the writer | MR-FU-03-8 |
| E40 | A leader asks for "the AI share of traffic" | The data cannot give one; AI referrals and flagged queries are both [floors](glossary.md#floor) | Report both as "at least" figures with their sources and dates, and say what the data cannot show. Do not estimate a share | MR-FU-03-6 |
| E90 | The check-up says [Python](glossary.md#python) is too old or missing | Python 3 is not installed or not on the path | Install Python 3 from the address in the [shopping list](shopping-list.md) and reopen the terminal | MR-FU-01-1 |
| E91 | The check-up says the kit folder is missing | The kit was not added, or you ran the command from the wrong folder | Run it from the repository folder and add the kit again | MR-FU-01-2 |
| E92 | The check-up says the settings file is missing | `config.json` was not made from `config.example.json` | Copy the example, rename the copy and fill it in | MR-FU-01-3 |
| E93 | The check-up says the settings file is invalid or a key is empty | A comma or quote is wrong, or a required field is blank | Open the file, fix the JSON and fill in the field it names. The check-up never shows what you typed | MR-FU-01-3 |
| E94 | The check-up says a key name is not set | The environment variable is missing from this terminal or the `.env` file | Set it again as shown in the guide. The check-up looks at names only | MR-FU-02-2 |
| E23 | A menu name in a guide does not exist on your screen | A vendor renamed or moved it | Search the vendor's help for the task name in quotes and use the newest page. Tell us the step ID so we update the guide | any |

Code E00 is not a problem. It means the check-up looked at everything it checks and found nothing wrong.
