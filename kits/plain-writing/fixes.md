# Fixes

Find what you see, then follow the fix. If your problem isn't here, send the [step ID](glossary.md#step-id) and any [support code](glossary.md#support-code) to Pigasus Group at https://pigasus.group/contact. Setup questions are free, and new problems get added to this table.

Codes from E90 to E95 come from the command-line check-up that every kit shares. They're explained in [getting help](../../guides/getting-help.md).

| Code | What you see | Why it happens | The fix | Step |
|---|---|---|---|---|
| E01 | You can't find where to [upload](glossary.md#upload) a [skill](glossary.md#skill) in Claude or ChatGPT | The menu has a different name on your plan or app version, or skills are off for your account | Look under Settings for Skills, Capabilities, or Customize. If it isn't there, use a [Project](glossary.md#project) instead (guide `PW-LC-02`). It does the same job for the writing rules | PW-LC-01-2 |
| E02 | The upload is rejected, or the skill shows with no name | The zip has an extra folder layer, or the folder name doesn't match the skill name | Download the zip again from the Releases page and upload it without opening or renaming it | PW-LC-01-3 |
| E03 | A Google sign-in screen keeps coming back | A browser setting is blocking sign-in cookies, or you're signed in to two Google accounts | Open a private browser window, sign in once, and try again | PW-FR-02-1 |
| E04 | ChatGPT says it can't use a file | The file type isn't supported in that place, or the file is too large | Upload the `.md` files from the kit as they are. Don't upload `.py` files to a [Custom GPT](glossary.md#custom-gpt) | PW-LC-02-3 |
| E05 | The [AI model](glossary.md#ai-model) says your pasted [prompt](glossary.md#prompt) is too long, or it answers only part of the rules | The chat window has a length limit, or the paste was cut off | Paste the prompt in two parts, or use a Project (guide `PW-LC-02`), which holds the rules for you | PW-FR-01-4 |
| E06 | The AI model follows the rules at first, then goes back to old habits | In a long chat, early instructions fade | Paste Prompt 1 again, or start a new chat for each piece | PW-FR-04-3 |
| E07 | Google says "Google hasn't verified this app" when you run the [script](glossary.md#script) | [Apps Script](glossary.md#apps-script) you wrote yourself isn't reviewed by Google. The warning is normal for your own script | Click Advanced, then the "Go to" link at the bottom, then Continue. The script only touches the Doc it's attached to | PW-LC-03-5 |
| E08 | The "Plain writing" and "Kit help" menus don't appear in your Doc | The Doc needs a reload after the script is saved, or the script was saved in a different project | Reload the Doc. If they're still missing, make sure the script was opened from this Doc's Extensions menu | PW-LC-03-6 |
| E09 | The menu asks for permission every time | The first approval didn't finish | Run any menu item, click Review permissions, pick your account, then Continue | PW-LC-03-5 |
| E10 | The check-up says the script isn't attached to a Doc | You created the script from script.google.com and not from inside a Doc | Open your Doc, then Extensions, then Apps Script, and paste the script there | PW-LC-03-2 |
| E11 | The check-up says the word lists are empty | The paste was cut short, so part of the script is missing | Select all in the script editor, delete, and paste the whole file again | PW-LC-03-3 |
| E12 | The check-up says a word pattern isn't valid | A quote mark or bracket changed while copying | Paste the file again from the raw view on GitHub (the Raw button), not from a formatted page | PW-LC-03-3 |
| E13 | The check-up says the script couldn't read the Doc | The script doesn't have permission yet | Run Plain writing, then Show count report, approve the permission request, and run the check-up again | PW-LC-03-6 |
| E14 | The [command line](glossary.md#command-line) says `python3: command not found` | [Python](glossary.md#python) isn't installed, or on Windows the command is `python` or `py` | Install Python (guide `PW-FU-01`). On Windows, use `py` in place of `python3` everywhere | PW-FU-01-3 |
| E15 | `FATAL: could not load canonical style rules` | The `data/style_rules.json` file was moved or deleted, or you ran the script from a different copy of the folder | Put the `data` folder back next to `scripts`, or point to your own copy | PW-FU-03-2 |
| E16 | `FATAL: unknown key(s) in ...` | Your rules file has a key the checker doesn't know. A typo is the usual cause | Compare your file to `data/brand-rules/example.json` and fix the spelling of the key named in the message | PW-FU-04-3 |
| E17 | A short memo fails on "No internal links," "No FAQ," or a word count | You ran the blog checks on something that isn't a blog post | Add `--prose` to the command so the checker only looks at the writing | PW-FU-03-2 |
| E18 | The [gate](glossary.md#gate) says "Could not find these skills" | The three checker folders aren't side by side | Keep `article-check`, `tell-scorer`, `copy-lint`, and `plain-writing` in the same parent folder, or pass `--skills-dir` | PW-FU-05-2 |
| E19 | A draft you're proud of fails the tell-score gate | The default limits are strict starting points, and a short draft with one banned word can break a per-1,000-word limit | Read the line that failed. Fix the word it found. For short pieces, raise the limit in your own [thresholds](glossary.md#threshold) file | PW-FU-04-4 |
| E20 | The checker says the file isn't found, or prints garbled text | The file is a Word or PDF file, not plain text or [markdown](glossary.md#markdown) | Copy the text into a file ending in `.md`, or in Google Docs use File, Download, Markdown | PW-FU-03-1 |
| E21 | `copy-lint` ends with exit code 2 and no findings | It couldn't run, usually because a settings file has an unknown key | Run it with `--explain` to see which settings file it read, and fix the key it names | PW-FU-03-4 |
| E22 | [Git](glossary.md#git) refuses to save your change and prints the gate's findings | The pre-commit [hook](glossary.md#hook) is working. A draft failed a check | Fix the findings and save again. To skip once, only if you've read them, add `--no-verify` to the command | PW-FU-05-5 |
| E23 | The AI model makes up a statistic or a source | AI models write plausible numbers when they have none | Run the claims prompt (Prompt 4) or the evidence-review skill. Delete any number you can't open a source for | PW-FR-04-4 |
| E24 | A rule fires on something that's correct (a quote from someone else, a product name) | The rules look at words, not meaning | Keep the original wording if it's a quote or a name, and add the exception to your [house style](glossary.md#house-style) so the next reader knows why | PW-FR-03-4 |
