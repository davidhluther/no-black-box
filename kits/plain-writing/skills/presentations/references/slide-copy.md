# Slide Copy

## The Assertion Headline Rule

Every slide headline must be an assertion — a complete thought that states a conclusion. If you read only the headlines in sequence, they should tell the entire story of the presentation.

**Good headlines (assertions):**
- "Patient fall rates drop 34% with integrated bed alert systems"
- "Three recurring compliance gaps drive 80% of audit findings"
- "A staged pilot reduces implementation risk while proving ROI"

**Bad headlines (labels):**
- "Our Solution"
- "Key Benefits"
- "Implementation Timeline"
- "About Us"

### The Silent Read Test

Print or display the deck. Read only the headlines, in order. Do they tell a coherent, persuasive story? If not, rewrite the headlines until they do.

## One Message Per Slide

Every slide must serve exactly one Message. If a slide serves no Message, cut it. If a slide tries to serve two Messages, split it.

Before building, map each slide to its Message:

```
Slide 1: [Title slide — states the outcome for the audience]
Slide 2: [Message 1 — Think] "Industry faces three converging pressures..."
Slide 3: [Message 1 — Feel] "Organizations that delay see 2x cost escalation..."
Slide 4: [Message 2 — Believe] "Case: Regional Health reduced falls by 34%..."
...
```

## Evidence Types

Match the evidence type to the cognitive target:

| Target | Evidence Type | Example |
|--------|--------------|---------|
| Think | Data, metrics, benchmarks | "34% reduction in falls across 12 facilities" |
| Feel | Consequences, stories, implications | "Every unaddressed fall costs $35K and triggers a review cycle" |
| Believe | Mini-cases, references, operational artifacts | "Regional Health pilot: 90-day deployment → 34% fall reduction → system-wide rollout" |

## Mini-Cases Replace Logo Walls

Never use a slide full of client logos. Replace with outcome tiles:

```
[Client or anonymized] | [Problem] | [Action] | [Result with metric]
```

4-6 tiles per slide. Each one is Problem → Action → Result. If you must show logos, segment them by relevance to this audience — not alphabetically or by size.

## Speaker Notes

The slide is not the presentation. The presenter is. Speaker notes should contain:

- The actual talking points (what you say out loud)
- Transition language to the next slide
- Designed questions to ask the audience (TEDY: Tell me, Explain, Describe, Your view on...)
- Timing cues if the presentation has time constraints
- Contingency notes (if they ask X, go to slide Y)

## The Story Template (for anecdotes within the deck)

When including a story or anecdote, use this structure (keep it to 30-90 seconds when spoken):

1. **Overarching point** — What is this story proving?
2. **Situation** — A specific person, place, thing, or event
3. **Challenge** — What disrupted the status quo?
4. **Result** — What happened? What is the new reality?
5. **So what?** — How does this connect back to the point?

## Common Copy Traps

| Trap | Fix |
|------|-----|
| "We do everything" slide | Focus on 2-3 patterns relevant to THIS audience |
| Feature parade | Tie every feature to a decision criterion or business value |
| "No risk" assertions | Show risk handling and proof strength instead |
| Vague value claims ("high quality") | Replace with operational artifacts — QA gates, defect trends, NPS |
| Growth brags ("fastest growing") | Reframe as capacity + reliability: "Added 3 pods; maintained NPS 65; 98% on-time" |
| Patriotic/stock imagery | Remove unless directly tied to a Message |
