# What David Built

David Luther built the first version of these tools while working on content at Corpay, and rebuilt them here for organizations of any size. This page says what problem they solve, what he made, and what it shows about how he works.

## The problem

Writing that comes out of an [AI model](glossary.md#ai-model) has a recognizable sound. It opens with stage-setting, leans on a handful of favorite words, ends with a recap, and announces its own importance. Readers pick up on it quickly, and they stop trusting what comes next.

On that content team, David saw the same corrections happen draft after draft. A reviewer would fix a stiff opener, and the next draft would have a different stiff opener. The rules lived in people's heads and in a long document nobody reread. Each round of review spent human attention on things a program could have caught.

A small organization has the same problem with less help. A volunteer writing a grant or a newsletter has no editor, and a consultant who sells one template to every client doesn't fix it either.

## What David built

He wrote the rules down with the reasoning beside each one, so a reader can judge whether a rule fits instead of obeying it blindly. Then he turned the rules into tools.

- A [style guide](glossary.md#style-guide) in tiers. Hard bans, overuse watches, sentence shapes, mechanics, and a final tier about structure, because the structure of a whole piece is harder to hide than its vocabulary.
- A [validator](glossary.md#validator) that reads a draft and lists every violation with its line, so a person doesn't have to hunt.
- A scorer that counts each rule across a whole set of pages and compares before and after, so a change in the rules can be judged by what actually changed in the writing.
- A [linter](glossary.md#linter) for finished web pages, because a menu label or a page title never passes through a draft check, and that's where the mistakes kept hiding.
- An evidence review, a method for grading claims and statistics before anything reaches a board, a funder, or the public.
- Voice presets built from his own published writing, so the tools can write in a particular voice and still follow the rules.
- A [house style](glossary.md#house-style) layer, so one shared set of rules serves many organizations, each with its own short file on top.

The kit also carries some hard-won lessons about process. A rule that exists only in prose doesn't hold, so each rule got a program or a checkbox in the same change that wrote it down. Banning one habit tends to push writers toward a nearby one, so the scorer compares before and after and watches the neighbors. And when David tested whether these rules mattered to how AI search tools cite pages, he found no measured benefit from avoiding the language tells, so the guide justifies every rule as editorial quality for the reader and never as a ranking trick. The tools warn about formatting and never strip it.

## What changed

Reviews got shorter and moved to higher ground. The mechanical problems were caught before a person read the draft, so reviewers could spend their time on whether the piece was true, specific, and useful. People could see which rules were doing work and which weren't, because the scorer measured it. New writers learned the standards faster, because the reasons were written down.

This kit is the public version. It leaves out the employer's own brand rules and data, and keeps the method, the lists, and the programs.

## Skills it shows

- Editorial judgment. Knowing which rules are about the reader and which are habits, and writing the difference down.
- Systems thinking. Turning a style guide into checks that run at the right moment, and into a layer system so one baseline serves many organizations.
- Measurement design. Counting each rule on its own, comparing before and after, and watching for displacement instead of declaring victory.
- Research discipline. Testing a belief before building on it, and reporting a null result honestly.
- [Python](glossary.md#python) tooling. Small, readable, read-only programs with no secrets and no surprises.
- Writing for beginners. Defining each term where it first appears, and designing for someone who has never opened a [command line](glossary.md#command-line).

David Luther built this as part of Pigasus Group's work to make tools like these open to organizations that can't afford a consultant for every question. See [start here](start-here.md) for what the kit does and how to use it.
